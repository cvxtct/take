# Domain documentation

Take uses a single-context layout:

- `GLOSSARY.md` at the repository root for shared terminology.
- `docs/adr/` for architecture decision records.

Before exploring an area, read the glossary and relevant architecture decisions
if they exist. Use the glossary's terminology in code, tests, issues, and
explanations. Explicitly flag proposals that contradict a recorded decision.

If these documents do not exist, continue silently. Create entries and decision
records as terms or decisions are resolved, including through `domain-modeling`,
`grill-with-docs`, or `improve-codebase-architecture`. Do not create empty
placeholder documents just to satisfy this layout.
